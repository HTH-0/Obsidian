## 📘 1. 데이터베이스 기초 개념 ★★

- 릴레이션: 테이블
- 속성: 열
- 차수: 속성의 수
- 튜플: 행
- 카디널리티: 튜플의 수
- 도메인: 속성에 들어가는 원자값 집합

### 계산 공식
- 카디널리티: 곱연산 (예: 2 * 4 = 8)
- 차수: 합연산 (예: 3 + 3 = 6)

### 튜플 특징
- 튜플 간에는 **순서가 없음**

---

## 📘 2. DDL, DML, DCL ★★

### DDL (Data Definition Language) - 데이터 정의어
- CREATE: 테이블 생성
- ALTER: 테이블 속성 변경
- DROP: 테이블 삭제

### DML (Data Manipulation Language) - 데이터 조작어
- SELECT: 조회
- INSERT: 삽입
- UPDATE: 수정
- DELETE: 삭제

### DCL (Data Control Language) - 데이터 제어어
- GRANT: 권한 부여
- REVOKE: 권한 회수
- COMMIT: 결과 반영
- ROLLBACK: 결과 되돌리기

---

## 📘 3. SQL 명령어 (기출) ★

- DISTINCT: 중복 제거 (SELECT 절에서 사용)
- CASCADE: 부모 삭제 시 자식도 삭제
- ALTER: 릴레이션 속성 수정
- BETWEEN AND: 범위 검색 (짝지어 사용)
- UPDATE SET: 수정 (짝지어 사용)

---

## 📘 4. 후보키 vs 슈퍼키 ★★★

- **후보키**: 유일성 + 최소성 만족
- **슈퍼키**: 유일성 만족, 최소성은 불만족
- **기본키**: null, 중복 불가
- **외래키**: 다른 릴레이션의 기본키 참조
- **대체키**: 기본키를 대신할 수 있는 후보키

---

## 📘 5. 로킹 (Locking) ★★★

- 트랜잭션이 데이터 접근 중 해당 데이터를 잠그는 것
- **로킹 단위 커질수록**: 로크 수↓, 병행성↓, 오버헤드↓, 공유도↓, 관리 용이
- **로킹 단위 작아질수록**: 반대

---

## 📘 6. 정규화 ★★★

비정규 → 제1정규형 → 제2정규형 → 제3정규형 → BCNF → 제4정규형 → 제5정규형

### 정규화 조건
- 제1정규: 원자값 도메인
- 제2정규: 부분적 함수 종속 제거
- 제3정규: 이행적 함수 종속 제거
- BCNF: 후보키가 아닌 결정자 제거
- 제4정규: 다치 종속 제거
- 제5정규: 조인 종속 제거

📌 키워드 암기: `도부이 결다조`

### 이행적 함수 종속
- A → B, B → C이면 A → C → 이행적 종속

---

## 📘 7. 트랜잭션 특징 (ACID) ★★★

- **Automicity (원자성)**: 전부 반영 or 전혀 반영 X
- **Consistency (일관성)**: 일관된 상태 유지
- **Isolation (격리성)**: 동시에 수행돼도 독립적으로
- **Durability (영속성)**: 고장 나도 결과 유지

---

## 📘 8. 무결성 ★★

- **개체 무결성**: 기본키는 null, 중복 불가
- **참조 무결성**: 외래키는 null 또는 참조 릴레이션의 기본키
- **도메인 무결성**: 속성 값이 정의된 도메인 값이어야 함

---

## 📘 9. 관계 대수 연산 ★★

관계형 데이터베이스의 절차적 질의 언어

- **SELECT (σ)**: 조건에 맞는 튜플
- **PROJECT (π)**: 특정 속성만 선택
- **JOIN (▷◁)**: 릴레이션 합침
- **DIVISION (÷)**: 특정 속성 제거하고 출력

📌 관계 대수 = **절차적 언어**, 비절차적이라 하면 오답

---

## 📘 10. 뷰 (View) ★★

- 테이블 기반 가상 테이블
- 논리적 존재, 실제 데이터는 없음
- 원본 테이블 삭제 시 뷰도 삭제됨
- 뷰 위에 다른 뷰 정의 가능
- 삽입/갱신/삭제 제약 있음
- CREATE, DROP 가능 / ALTER 불가

---

## 📘 11. 데이터베이스 목표 (투명성) ★★

- **위치 투명성**: 실제 위치 몰라도 접근 가능
- **중복 투명성**: 여러 곳 데이터 → 하나처럼 보임
- **병행 투명성**: 다중 트랜잭션에도 결과 일관성
- **장애 투명성**: 장애 발생해도 트랜잭션 보장
- **분할 투명성**: 데이터 조각이 어디 있어도 통합된 것처럼 작동

---

## 📘 12. 물리적 설계 vs 논리적 설계 ★★

### 물리적 설계
- 레코드 집중 분석
- 저장 양식/경로 설계
- 접근 경로 설계

### 논리적 설계
- 논리 구조 매핑
- 트랜잭션 인터페이스 설계
- 스키마 평가 및 정제
