## 📘 2. UI 설계 원칙

### 🎯 UI 4대 설계 원칙

|원칙|설명|
|---|---|
|직관성|누구나 쉽게 이해하고 사용할 수 있어야 함|
|유효성|사용자의 목적을 정확히 달성할 수 있어야 함|
|학습성|누구나 쉽게 배우고 익힐 수 있어야 함|
|유연성|사용자 요구 최대한 수용, 오류 최소화|

> ※ 오류를 숨기면 안됨

### 🧩 UI 종류

|종류|설명|
|---|---|
|CLI (Command Line Interface)|명령어 기반 UI (예: cmd)|
|GUI (Graphic User Interface)|마우스 클릭 기반 그래픽 UI|
|NUI (Natural User Interface)|제스처, 동작 기반 UI|
|VUI (Voice User Interface)|음성 기반 UI|
|OUI (Organic User Interface)|사물과 상호작용하는 UI|

## 📘 3. 요구사항

### 📌 요구사항 유형

|분류|설명|예시|
|---|---|---|
|기능적 요구사항|시스템이 **무엇을** 해야 하는가|송금, 조회, 인출 등|
|비기능적 요구사항|시스템의 **품질**과 관련|응답속도, 보안, 성능 등|

> 기능 유무 → 기능적 / 성능 기준 → 비기능적

### 🔄 요구사항 개발 프로세스

```
도출 → 분석 → 명세 → 확인
```

### 🔍 요구사항 검토 방법

|방식|설명|
|---|---|
|Peer Review (동료 검토)|작성자가 직접 설명하며 결함 확인|
|Walk Through (워크스루)|미리 배포, 가벼운 회의로 검토|
|Inspection (인스펙션)|전문가 중심의 형식적 리뷰|

|단계|설명|표현|
|---|---|---|
|객체 모델링|객체 도출, 관계 정의|객체 다이어그램|

## 📘 8. 하향식 vs 상향식 설계

|구분|설명|
|---|---|
|하향식|절차 지향, 상위 컴포넌트 → 하위 기능|
|상향식|객체 지향, 하위 모듈 → 상위 조립, 기능 추가 어려움|

> 암기 팁: 상사에게 올라가기 어렵다 = **상향식은 추가 어려움**

## 📘 11. 디자인 패턴 (GoF)

### 생성 패턴

- **Abstract Factory**: 관련 객체 집합 생성
    
- **Builder**: 조립 방식으로 객체 생성
    
- **Factory Method**: 생성 책임을 서브클래스에 위임
    
- **Prototype**: 복제
    
- **Singleton**: 하나의 인스턴스만 존재
    

### 구조 패턴

- **Adapter**: 인터페이스 변환
    
- **Bridge**: 구현/추상화 분리
    
- **Composite**: 단일/복합 객체 통합
    
- **Decorator**: 상속 없이 기능 확장
    
- **Facade**: 간단한 인터페이스 제공
    
- **Flyweight**: 메모리 절약, 인스턴스 공유
    
- **Proxy**: 대리자 역할
    

### 행위 패턴

- **Observer**, **State**, **Strategy**, **Template**, **Command**, **Iterator** 등
