## 🔍 @Controller

### ✅ 역할

- 이 클래스가 **Spring MVC의 컨트롤러(Controller) 역할을 한다는 것을 선언**
    
- 클라이언트 요청을 처리하고, **뷰 이름 또는 JSON 등의 결과를 반환**
    

### 🧠 동작 원리

- `@Component`의 확장으로, **컴포넌트 스캔 대상**
    
- 내부적으로 `DispatcherServlet`이 이 클래스를 찾아서 요청 매핑을 연결함

## 🔍 @Slf4j (롬복 제공)

### ✅ 역할

- `log`라는 이름의 **로깅 객체(Logger)**를 자동 생성해주는 롬복 어노테이션
    
- 별도로 `Logger logger = LoggerFactory.getLogger(...);` 선언 안 해도 됨
    

### 🧠 사용 예

```java
log.info("GET 요청 들어옴");
log.debug("파라미터 값: {}", value);
```

이렇게 `log` 객체를 그냥 쓰면 됨.

> 전제: 롬복(Lombok) 플러그인 및 `@Slf4j` 어노테이션 사용 설정이 되어 있어야 함.

## 🔍 @RequestMapping("/param")

### ✅ 역할

- 이 컨트롤러 클래스의 **기본 URL 경로**를 지정
    
- `"/param"`으로 시작하는 모든 요청은 이 컨트롤러가 처리
    

### 🧠 예시

```java
@Controller
@RequestMapping("/param")
public class ParameterController {

    @GetMapping("/test")
    public String test() {
        return "testPage"; // 실제 경로: /param/test
    }
}
```

- `/param/test`로 요청하면 `test()` 메서드 실행
    
- 이 클래스 안의 메서드들이 `/param` 경로를 기반으로 동작

## 🧩 요약

|어노테이션|설명|
|---|---|
|`@Controller`|이 클래스가 컨트롤러임을 명시. 스프링이 관리하게 함|
|`@Slf4j`|`log` 객체 자동 생성 (로그 출력용, Lombok 제공)|
|`@RequestMapping`|클래스나 메서드 수준에서 URL 경로 매핑 지정|
