# 🌐 Spring MVC 요청 매핑 & 데이터 처리 어노테이션 정리

---

## 📌 1. 요청 URI 매핑 어노테이션

|어노테이션|옵션|설명|
|---|---|---|
|`@RequestMapping`|`value` / `path`|매핑할 URI 경로 지정 (`@GetMapping`, `@PostMapping`의 상위 개념)|
||`method`|요청 HTTP 메서드 지정 (ex. `RequestMethod.GET`)|
||`params`|특정 파라미터 존재 여부로 매핑 제한|
||`headers`|요청 헤더로 매핑 제한|
||`consumes`|요청의 Content-Type 제한 (ex. `application/json`)|
||`produces`|응답의 Content-Type 제한 (ex. `application/json`)|
|`@GetMapping`|없음|`@RequestMapping(method = RequestMethod.GET)`의 축약형|
|`@PostMapping`|없음|`@RequestMapping(method = RequestMethod.POST)`의 축약형|
|`@PutMapping`|없음|`@RequestMapping(method = RequestMethod.PUT)`의 축약형|
|`@DeleteMapping`|없음|`@RequestMapping(method = RequestMethod.DELETE)`의 축약형|

### 🔎 실무 팁

- `@RequestMapping`은 유연하지만 **가독성이 떨어지기 때문에**, 대부분은 `@GetMapping`, `@PostMapping`을 사용
    
- `produces = "application/json"` 같은 속성은 주로 API 서버에서 사용

## 📌 2. 요청 파라미터 매핑 어노테이션

|어노테이션|옵션|설명|
|---|---|---|
|`@RequestParam`|`value`|파라미터 이름 지정 (`@RequestParam("id") String id`)|
||`required`|필수 여부 (`true`일 경우 없으면 400 오류)|
||`defaultValue`|기본값 설정 (값이 없으면 대체)|
|`@RequestBody`|없음|요청 body를 Java 객체로 변환 (JSON, XML → DTO)|
|`@PathVariable`|없음|URI 경로 내의 변수를 바인딩 (`/user/{id}` → `@PathVariable String id`)|
|`@ModelAttribute`|없음|파라미터를 객체로 바인딩 (폼 데이터 → DTO)|

### 🔎 실무 팁

- `@RequestParam`은 form 또는 query string 처리에 적합
    
- `@RequestBody`는 REST API에서 **JSON 요청 처리의 핵심**
    
- `@ModelAttribute`는 HTML form 전송 시 DTO로 바인딩할 때 유용
    
- `@PathVariable`은 `RESTful` 스타일 URL에서 필수

## 📌 3. 뷰(View)와 데이터 전달 관련 클래스

|클래스|설명|
|---|---|
|`Model`|`addAttribute()`로 데이터를 뷰에 전달|
|`ModelMap`|`Model`과 거의 동일, `Map` 기반|
|`ModelAndView`|뷰 이름과 데이터 모두 지정하고 싶을 때 사용|
|`Map<String, Object>`|컨트롤러 메서드에서 파라미터로 넣으면 Model처럼 작동함|

---

## 📌 4. 리다이렉트 & 포워딩

|리턴 형태|설명|
|---|---|
|`"forward:/uri"`|서버 내에서 포워딩 (URL 변경 없음)|
|`"redirect:/uri"`|클라이언트에게 리다이렉트 (URL 변경됨)|
|`RedirectAttributes`|리다이렉트 시 **데이터를 임시로 전달**할 수 있는 객체 (ex. 플래시 메시지)|

### 🔎 실무 팁

- `redirectAttributes.addFlashAttribute("msg", "성공!")` 하면, 리다이렉트 후 한 번만 사용할 수 있음
    
- 포워딩은 JSP 기반 MVC에서 사용, REST API에서는 거의 안 씀

## 🧠 추가로 알아두면 좋은 것들

### ✅ JSON 처리 흐름

```java
@PostMapping("/api/save")
public ResponseEntity<MyDto> save(@RequestBody MyDto dto) {
    return ResponseEntity.ok(dto);
}
```

- `@RequestBody`: 요청 바디(JSON → DTO)
    
- `ResponseEntity`: 응답의 본문 + 상태코드를 함께 보낼 수 있음
    
- 기본적으로 Jackson이 내부에서 JSON 직렬화/역직렬화 담당
    

---

### ✅ URI Path 처리 예

```java
@GetMapping("/user/{id}")
public String getUser(@PathVariable("id") Long userId) {
    // /user/10 → userId = 10
}
```

---

### ✅ 파라미터 처리 예

```java
@GetMapping("/search")
public String search(@RequestParam(defaultValue = "1") int page,
                     @RequestParam String keyword) {
    // /search?page=2&keyword=java
}
```

## ✅ 요약 표 (전체 핵심만 압축)

|분류|어노테이션 / 클래스|역할|
|---|---|---|
|URI 매핑|`@RequestMapping`, `@GetMapping` 등|URL + HTTP method 매핑|
|파라미터 매핑|`@RequestParam`, `@RequestBody`, `@PathVariable`, `@ModelAttribute`|요청 데이터 → 메서드 파라미터로 바인딩|
|뷰 처리|`Model`, `ModelAndView`|컨트롤러 → 뷰로 데이터 전달|
|리다이렉트 처리|`"redirect:/..."`, `RedirectAttributes`|리다이렉트 + 데이터 전달|
