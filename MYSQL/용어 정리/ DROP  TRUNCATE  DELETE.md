## ✅ DROP / TRUNCATE / DELETE 비교 정리표

|항목|**DROP**|**TRUNCATE**|**DELETE**|
|---|---|---|---|
|명령어 종류|DDL (데이터 정의어)|DDL (일부 DML 성격 포함)|DML (데이터 조작어)|
|Rollback 여부|❌ 불가능|❌ 불가능|✅ 가능 (COMMIT 전까지)|
|COMMIT 동작|자동 커밋 (Auto Commit)|자동 커밋 (Auto Commit)|사용자가 직접 COMMIT|
|Storage 처리|테이블이 사용하던 **모든 저장공간 해제**|일부 Storage만 해제 (초기 구조 남김)|Storage 유지됨|
|정의 삭제 여부|테이블 **정의 자체도 삭제**|테이블 정의는 **유지됨**|테이블 정의 유지|
|사용 목적|테이블 자체를 완전히 삭제|**모든 데이터 삭제 + 초기화**|조건별로 **데이터만 삭제**|

---

## ✅ 핵심 요약 문장

- **DROP**: 테이블 자체를 **완전히 없앰** (정의 + 데이터 + 공간 모두 삭제)
    
- **TRUNCATE**: 테이블은 유지하고, **전체 데이터만 빠르게 삭제**
    
- **DELETE**: **선택적으로 데이터만 삭제** (조건 가능, 롤백 가능)
    

---

## ✅ 실무 사용 팁

|상황|추천 명령|
|---|---|
|테이블 자체가 더 이상 필요 없음|`DROP`|
|전체 데이터 초기화 (로그 테이블 등)|`TRUNCATE`|
|특정 조건의 데이터만 지우고 싶을 때|`DELETE WHERE ...`|

---

## ✅ 시험 대비 암기 포인트

> DROP은 테이블 **증발**  
> TRUNCATE는 데이터만 **쓸어버림**  
> DELETE는 **조건부 삭제 + 롤백 가능**
