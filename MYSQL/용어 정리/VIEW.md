## ✅ 뷰(View)란?

- **하나 이상의 테이블을 기반으로 생성된 가상의 테이블**
    
- 실제 데이터를 저장하지 않고, **SQL 쿼리의 결과를 테이블처럼 보여줌**
    
- **SELECT 문을 저장**해두고 테이블처럼 사용할 수 있음
    

---

## ✅ 뷰의 주요 목적

|목적|설명|
|---|---|
|데이터 추상화|사용자에게 **필요한 데이터만** 보여주기|
|보안|민감한 정보는 숨기고 보여줄 열만 선택 가능|
|편의성|자주 쓰는 복잡한 SQL을 뷰로 만들어 **간단히 재사용** 가능|
|독립성|테이블 구조가 바뀌어도 **응용 프로그램 변경 최소화**|

---

## ✅ 뷰의 장점

1. **독립성**
    
    - 테이블 구조 변경 시에도 뷰를 사용하는 애플리케이션은 수정이 필요 없음  
        → 추상화 역할
        
2. **편리성**
    
    - 복잡한 SQL을 간단히 재사용 가능
        
    - 예: `JOIN`, `집계` 쿼리를 뷰로 만들어두고 쉽게 조회
        
3. **보안성**
    
    - 민감한 정보를 **제외한 컬럼만 포함된 뷰** 제공 가능
        
    - 예: 급여, 성적 등 감추고 싶은 정보를 감출 수 있음
        

---

## ⚠️ 뷰의 단점 (주의사항)

|항목|설명|
|---|---|
|성능 저하|복잡한 뷰를 여러 번 중첩해서 사용할 경우 성능에 악영향|
|제한된 갱신|**뷰를 통해 직접 UPDATE/DELETE**가 불가능한 경우 존재 (ex. 조인 포함, 그룹 함수 포함 등)|
|실데이터 X|뷰는 데이터를 저장하지 않으므로 뷰 자체는 디스크 공간 차지하지 않음 (단, **물리적 뷰는 예외**)|

---

## ✅ 뷰의 종류

|종류|설명|
|---|---|
|**단순 뷰**|하나의 테이블 기반, DML(삽입/수정/삭제) 가능|
|**복합 뷰**|JOIN, 집계, GROUP BY 포함 → DML 제한 있음|
|**인라인 뷰**|`FROM (SELECT ...)` 형태로 쿼리 안에서 직접 사용하는 임시 뷰|
|**물리적 뷰 (Materialized View)**|쿼리 결과를 **실제로 저장**하는 뷰, 성능 향상 목적|

---

## ✅ 뷰 예시

```sql
-- 예: 급여 정보를 제외한 직원 정보 뷰
CREATE VIEW 직원_공개뷰 AS
SELECT 사번, 이름, 부서
FROM 직원;
```

```sql
-- 사용
SELECT * FROM 직원_공개뷰;
```
