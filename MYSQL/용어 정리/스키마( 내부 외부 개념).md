## 🏦 [은행 시스템 예시]

### 💡 전체적인 개요

은행에는 다양한 사용자들이 있고, 시스템은 이를 효율적으로 저장하고 보여줘야 해.

---

## 1️⃣ **개념 스키마 (Conceptual Schema)**

> 시스템 전체의 **논리적 구조**  
> 테이블, 속성, 관계, 제약조건 등

```sql
-- 논리적 구조 (예: MySQL ERD 기준)
고객(고객ID, 이름, 전화번호)
계좌(계좌번호, 고객ID, 잔액)
```

- **고객과 계좌는 1:N 관계**
    
- **고객ID는 기본키**, 계좌 테이블에서는 **외래키**
    

🟰 = 전체 시스템의 설계도

---

## 2️⃣ **내부 스키마 (Internal Schema)**

> 실제 데이터를 **물리적으로 어떻게 저장할지** 정의  
> 인덱스, 저장 경로, 페이지 크기, 파일 구조 등

예:

- `고객` 테이블은 `/data/customer.ibd` 파일에 저장
    
- `계좌` 테이블은 B-Tree 인덱스를 사용
    
- `전화번호`는 압축 저장
    
- InnoDB 스토리지 엔진 사용
    
- 블록당 16KB로 페이지 구성
    

🟰 = 하드디스크 위의 저장 방식 설명서

---

## 3️⃣ **외부 스키마 (External Schema)**

> **사용자 관점에서 필요한 데이터 뷰**

예:

- **텔러(은행 직원)**:
    
    ```sql
    SELECT 이름, 계좌번호, 잔액
    FROM 고객 JOIN 계좌 ON 고객.고객ID = 계좌.고객ID;
    ```
    
- **관리자**:
    
    ```sql
    SELECT 고객ID, 이름, 전화번호 FROM 고객;
    ```
    
- **앱 사용자(모바일 뱅킹)**:
    
    ```sql
    SELECT 계좌번호, 잔액 FROM 계좌 WHERE 고객ID = '1234';
    ```
    

🟰 = 사용 목적별로 "필요한 것만 보여주는 뷰"

## 📌 요약 정리

|구분|관점|예시 내용|
|---|---|---|
|외부 스키마|사용자 뷰|모바일 앱 사용자에게 계좌번호/잔액만 보여줌|
|개념 스키마|전체 설계|고객, 계좌 테이블 구조와 관계 정의|
|내부 스키마|물리 저장|디스크 구조, 인덱스, 압축 방식 등|
