## ✅ 트랜잭션(Transaction) 정리

---

### 🔷 1. 트랜잭션이란?

> **하나의 논리적인 작업 단위**로서, 데이터베이스의 상태를 변화시키기 위한 하나 이상의 SQL 문장을 모은 것

- 트랜잭션은 전부 **성공**하거나, 전부 **실패 후 원상복구**되어야 함
    

---

### 🔷 2. 트랜잭션의 4대 특성 (ACID)

|약어|이름|설명|
|---|---|---|
|**A**|원자성 (Atomicity)|모두 실행되거나 모두 취소되어야 함 (All or Nothing)|
|**C**|일관성 (Consistency)|트랜잭션 전후 데이터 무결성 유지|
|**I**|고립성 (Isolation)|동시에 여러 트랜잭션이 실행되어도 서로 영향 없음|
|**D**|지속성 (Durability)|COMMIT된 데이터는 장애 발생 후에도 보존됨|

---

### 🔷 3. 트랜잭션 제어 명령어

|명령어|의미|
|---|---|
|`BEGIN TRANSACTION`|트랜잭션 시작|
|`COMMIT`|트랜잭션 **성공 확정**, 영구 반영|
|`ROLLBACK`|트랜잭션 **실패 시 전체 취소**|
|`SAVEPOINT 이름`|중간 지점 설정 (부분 롤백 가능)|
|`ROLLBACK TO SAVEPOINT 이름`|해당 지점까지 롤백 (일부 취소)|

---

### 🔷 4. 트랜잭션 예시

```sql
BEGIN TRANSACTION;

UPDATE account SET balance = balance - 10000 WHERE user_id = 'A';
UPDATE account SET balance = balance + 10000 WHERE user_id = 'B';

IF 오류 발생 THEN
  ROLLBACK;
ELSE
  COMMIT;
END IF;
```

---

### 🔷 5. 트랜잭션 고립성 레벨 (Isolation Level)

|수준|특징|현상 방지|
|---|---|---|
|**READ UNCOMMITTED**|가장 낮은 수준, Dirty Read 발생|없음|
|**READ COMMITTED**|커밋된 데이터만 읽음|Dirty Read 방지|
|**REPEATABLE READ**|같은 쿼리는 항상 같은 결과|Non-repeatable Read 방지|
|**SERIALIZABLE**|가장 높은 수준, 완전 격리|모든 고립성 보장 (느림)|

---

### 🔷 6. 실무 주의사항

- 트랜잭션은 너무 길어지면 **락(Lock)** 오래 유지되어 성능 저하 가능
    
- 꼭 필요한 단위로 묶고, **명확히 COMMIT 또는 ROLLBACK**할 것
    
- 자주 사용되는 패턴: `try-catch` 구조 + 예외 발생 시 `ROLLBACK`
    

---

## ✅ 요약 암기 문장

> "트랜잭션은 **All or Nothing**, ACID를 보장하며,  
> **BEGIN ~ COMMIT/ROLLBACK** 으로 제어한다."
