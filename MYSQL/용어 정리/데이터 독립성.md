
## ✅ 데이터 독립성이란?

> **"데이터베이스 구조(스키마)를 변경하더라도, 그 상위 계층에 영향을 주지 않도록 분리되어 있는 성질"**입니다.

즉,

- **물리적 구조 변경**이 논리 구조에 영향을 주지 않고,
    
- **논리 구조 변경**이 사용자 응용 프로그램에 영향을 주지 않는 것  
    → 이게 바로 데이터 독립성입니다.
    

---

## ✅ 데이터 독립성이 작동하는 구조

데이터베이스는 다음과 같은 **3단계 스키마 구조**로 구성되어 있어요:

|계층|설명|
|---|---|
|**외부 스키마 (External Schema)**|사용자 관점|
|**논리 스키마 (Conceptual Schema)**|설계자 관점|
|**내부 스키마 (Internal Schema)**|저장소 관점|

---

## ✅ 데이터 독립성의 두 종류

|구분|설명|예시|
|---|---|---|
|**논리적 독립성**|**논리 스키마 변경** 시 외부 스키마(사용자 View)에 영향 없음|새로운 컬럼 추가해도 기존 사용자 화면은 그대로|
|**물리적 독립성**|**내부 스키마 변경** 시 논리 스키마에 영향 없음|저장 위치 바꾸거나 인덱스 추가해도 테이블 구조는 그대로|

---

## ✅ 예시로 쉽게 이해하기

### 📌 논리적 독립성

```sql
-- 논리 구조 변경: 새로운 컬럼 추가
ALTER TABLE 고객 ADD 생년월일 DATE;

-- 기존 사용자 화면(View)에는 여전히 ID, 이름만 보임
SELECT 고객ID, 이름 FROM 고객뷰;
```

### 📌 물리적 독립성

- DBA가 **데이터 파일 위치 변경**, **인덱스 추가**, **파티셔닝**
    
- 하지만 SQL로 데이터를 조회하는 사람은 **변화를 느끼지 못함**
    

---

## ✅ 왜 중요한가?

|이유|설명|
|---|---|
|유연한 시스템 유지보수|하위 구조 변경해도 상위 구조 영향 최소화|
|개발 비용 절감|프로그램 수정 없이 DB 구조 개선 가능|
|추상화 수준 확보|사용자/개발자/DBA가 각자 필요한 수준의 구조만 다룸|

---

## ✅ 요약 문장

> **데이터 독립성**이란  
> **"스키마 계층 간 영향 없이 구조를 변경할 수 있는 능력"**을 의미하며,  
> **논리적 독립성**과 **물리적 독립성**으로 나뉜다.

---

A의 독립성 == A를 바꿀때 A의 상위 스키마의 변화가 없다
물리적 독립성 == 물리적 변화가 논리 스키마의 변화가 없다
