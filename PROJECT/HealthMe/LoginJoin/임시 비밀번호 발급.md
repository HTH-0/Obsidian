## ✉️ 임시 비밀번호 전송 로직 트러블슈팅 및 개선 사항

### 현재 구현

- 임시 비밀번호 발송 시 `Spring Boot Mail Starter`를 사용하여 이메일을 전송함.
    
- 해당 로직은 **동기 처리**로 동작하고 있어, 메일 서버의 응답 시간이 길어질 경우 전체 응답이 지연됨.
    
- 특히, 외부 SMTP(Gmail 등)를 사용할 경우 전송에 수 초가 소요되는 경우가 발생함.
    

### 임시 해결 방안

- 사용자 경험 보완을 위해, 버튼 클릭 시 "전송 중..." 등의 **로딩 텍스트를 동적으로 출력**하여 진행 중임을 명시함.
    
- 실제로 처리 시간은 동일하지만, **UX 상의 피드백을 제공함으로써 사용자의 불안감을 줄이는 효과**는 있음.
    

```jsx
<button disabled>{isLoading ? "이메일 전송 중..." : "임시 비밀번호 전송"}</button>
```

---

### 개선 필요 사항

- 이메일 전송 작업을 **비동기 처리**로 전환하는 것이 필요함.
    
- 대표적인 개선 방향:
    
    - `@Async` 사용하여 별도 쓰레드에서 메일 전송 수행
        
    - 이메일 발송 요청을 큐 기반으로 전송하고, 빠르게 응답 리턴 (e.g. Kafka, Redis Queue 등)
        
    - 이메일 전송 결과는 별도로 알림 또는 토스트 메시지로 후속 처리
        

```java
@Async
public void sendTemporaryPasswordEmail(String to, String password) {
    // 메일 구성 및 전송
}
```

- 장기적으로는 SMTP 서버 지연이나 실패에 대응할 수 있도록 **재시도 로직** 또는 **예외 메시지 정제**도 필요함.
    

---

### 정리

- 현재는 UX 측면에서 임시 대응 중이나, 실제 응답 성능 개선은 이루어지지 않음.
    
- 메일 전송은 네트워크 I/O이므로 반드시 **비동기 처리**가 요구되는 영역임.
    
- 사용자 경험과 시스템 안정성을 동시에 확보하려면, **비동기 전환 및 후속 처리 구조의 개선이 필요함**.
