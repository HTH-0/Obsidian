userid를 PK로 쓰지 않는 이유

- 변경 가능성 있음  
    사용자가 아이디 변경 요청할 수 있음 (예: apple → apple123).  
    PK가 되면 바뀌기 어려워짐. 다른 테이블 외래키까지 다 영향받음.
    
- 조인 성능 떨어짐  
    문자열 기반 키는 숫자보다 인덱스 느리고, 조인 시에도 성능 불리.  
    DB는 숫자를 더 빠르게 처리함.
    
- URL/API 노출 위험  
    /users/apple123 같은 형태로 외부에 식별자 노출됨.  
    개인정보처럼 보일 수 있고, 크롤링에도 취약.
    
- 외래키 관리가 번거로움  
    연관 테이블에 계속 문자형 키를 써야 함.  
    설계가 복잡해지고 유지보수 힘들어짐.
    
- 마이그레이션이나 시스템 연동 시 충돌 우려  
    다른 시스템에서 같은 userid가 존재할 수 있음.  
    내부 PK는 일관되게 숫자로 관리하는 게 안정적.
    
- 이메일도 마찬가지로 PK 설정 한다면 이메일 변경을 못함
