# ✅ JPA 양방향 관계 매핑 정리 - `@OneToMany` (User → Lend)

## 📘 1. 목표

- 기존 `Lend`에서 `@ManyToOne(fetch = LAZY)`로 `User`를 참조하고 있었음
    
- 이제 `User`에서도 `@OneToMany`로 대출 정보들을 조회할 수 있게 **양방향 매핑** 구성
    

---

## 📗 2. User.java에 @OneToMany 추가

### ✅ 변경 전 (단방향)

```java
@Entity
public class User {
    @Id
    private String username;
    private String password;
    private String role;
}
```

---

### ✅ 변경 후 (양방향 매핑 추가)

```java
@OneToMany(mappedBy = "user", cascade = CascadeType.ALL, orphanRemoval = true)
private List<Lend> lends = new ArrayList<>();
```

```java
@Entity
public class User {
    @Id
    @Column(length=100)
    private String username;

    @Column(nullable=false)
    private String password;

    private String role;

    @OneToMany(mappedBy = "user", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Lend> lends = new ArrayList<>();
}
```

> ✅ `mappedBy = "user"`는 Lend 엔티티의 `user` 필드와 연결됨  
> ✅ `cascade = ALL`: 사용자 저장 시 Lend도 함께 저장됨  
> ✅ `orphanRemoval = true`: 관계가 끊긴 Lend는 자동 삭제됨

---

## 🧪 3. 테스트 코드 예시

```java
@Test
@Transactional
public void test양방향조회() {
    User user = userRepository.findById("user1").get();
    List<Lend> lends = user.getLends(); // 여기서 Lend 목록 조회
    lends.forEach(System.out::println);
}
```

---

## 🔍 양방향 매핑 주의사항

|항목|설명|
|---|---|
|`mappedBy`|연관 관계의 주인 지정 (외래키 소유)|
|양방향 설정 목적|한쪽에서만 외래키 관리 + 반대편에서도 컬렉션 조회 가능|
|무한루프 방지|toString(), JSON 변환 시 순환참조 주의 필요 (e.g. @JsonIgnore)|
|연관관계 편의 메서드|addLend() 등으로 Lend와 User 간 관계 일관성 유지 필요|

---

## ✅ 요약

- `@OneToMany(mappedBy = "...")`를 통해 양방향 관계 설정
    
- 연관관계의 주인은 `@ManyToOne` 쪽 (Lend.user)
    
- LAZY 설정 시 `user.getLends()` 호출 시점에 쿼리 실행
    
- cascade와 orphanRemoval 설정으로 하위 엔티티 일괄 처리 가능
