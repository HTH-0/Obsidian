# ✅ 양방향 관계 삭제 처리 - 연관관계 끊기 vs `orphanRemoval=true`

---

## 📘 1. 상황 설명

```java
@OneToMany(mappedBy = "user", cascade = CascadeType.ALL, orphanRemoval = true)
private List<Lend> lends = new ArrayList<>();
```

- 위 코드는 `User → Lend` 양방향 관계
    
- 이때 Lend 데이터를 어떻게 삭제할 것인가?
    

---

## 📗 2. orphanRemoval이란?

- 부모 객체(User)에서 자식 객체(Lend)를 제거하면
    
- **DB에서도 자동으로 DELETE 쿼리 실행됨**
    

```java
user.getLends().remove(lend); // → lend row DELETE 됨
```

---

## ⚠️ orphanRemoval = false일 때는?

- 위 코드 실행 시 자식 엔티티는 **DB에서 삭제되지 않음**
    
- 단순히 연관관계만 끊어지고, row는 남아 있음
    

---

## 🧪 예시: 삭제 흐름

### ✅ 방법 1. 직접 삭제 (연관관계 유지 상태)

```java
lendRepository.delete(lend);
```

- 강제 삭제
    
- 부모 엔티티(User)는 그대로 유지됨
    

---

### ✅ 방법 2. 연관관계에서 제거 + orphanRemoval 적용

```java
user.getLends().remove(lend);
```

- orphanRemoval = true일 때만 DB에서 DELETE 발생
    
- `@Transactional` 범위 안에서만 작동
    

---

## ⚙️ 테스트 코드 예시

```java
@Test
@Transactional
public void testOrphanRemoval() {
    User user = userRepository.findById("user1").get();

    // 특정 Lend 하나 삭제
    Lend lendToDelete = user.getLends().get(0);
    user.getLends().remove(lendToDelete);

    // 변경사항 반영
    userRepository.save(user);
}
```

---

## 🧠 비교 요약

|방식|설명|특징|
|---|---|---|
|직접 삭제|`lendRepository.delete()`|즉시 삭제, 관계 유지 여부 무관|
|연관 끊기|`user.getLends().remove()`|`orphanRemoval = true`일 때만 DB에서도 삭제|
|`cascade = ALL`|부모 저장/삭제 시 자식도 함께|연관된 모든 자식에 적용됨|
|`orphanRemoval = true`|컬렉션에서 빠지면 삭제|**관계 단절 = 삭제 처리**|

---

## ✅ 최종 요약

- **삭제 방식**은 직접 삭제 vs 연관관계 제거 방식이 있음
    
- `orphanRemoval = true` 없으면 remove만 해서는 삭제 안 됨
    
- `cascade = ALL`은 저장/삭제 전파, `orphanRemoval = true`는 고아 객체 삭제
