# ✅ JPA 연관관계 편의 메서드 (addLend 등)

---

## 📘 1. 왜 필요한가?

- 양방향 관계에서는 **한쪽에서만 객체를 설정하면 반대쪽은 비어 있음**
    
- 즉, `lend.setUser(user)`만 하면 `user.getLends()`에는 해당 Lend가 없음
    
- 두 객체를 모두 연결하려면 양쪽을 모두 관리해야 함
    

---

## 📗 2. 잘못된 예시

```java
Lend lend = new Lend();
lend.setUser(user); // 반대편 관계는 비어 있음
lendRepository.save(lend);

System.out.println(user.getLends().size()); // 0 출력됨
```

---

## ✅ 해결 방법: 연관관계 편의 메서드 작성

### 📂 User.java

```java
public void addLend(Lend lend) {
    lends.add(lend);         // User → Lend
    lend.setUser(this);      // Lend → User
}
```

> ✅ 이 메서드를 통해 양쪽의 관계를 **동시에 일관성 있게 유지** 가능

---

## 🧪 예시 사용 코드

```java
@Test
@Transactional
public void test편의메서드() {
    User user = userRepository.findById("user1").get();
    Book book = bookRepository.findById(333L).get();

    Lend lend = new Lend();
    lend.setBook(book);

    user.addLend(lend); // 양쪽 연결됨
    userRepository.save(user); // cascade = ALL → lend 자동 저장
}
```

---

## 🧠 핵심 요약

|항목|설명|
|---|---|
|편의 메서드 역할|양방향 관계의 양쪽 필드 값 동기화|
|예시|`user.addLend(lend)` 내부에서 `lend.setUser(this)` 호출|
|저장 방식|`cascade = CascadeType.ALL` 설정 시 부모 저장으로 자식도 저장됨|
|유지 이점|조회, 삭제, 일괄 수정 등에서 관계 일관성 보장|

---

## ✅ 정리

- 양방향 관계에서는 **관계를 설정하는 책임**을 한 메서드에 몰아주는 게 좋음
    
- `addLend()`, `removeLend()` 같은 **편의 메서드로 관계 관리**하면 코드 안정성 상승
    
- 실제 프로젝트에서도 **편의 메서드 작성은 실무 관례**
