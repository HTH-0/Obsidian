# 📝 `String`, `StringBuilder`, `StringBuffer`의 차이

## 📌 내용 요약

- **문자열 연산 시 메모리 관리 차이** 학습
- **`String` vs `StringBuilder` vs `StringBuffer`** 비교
- **`System.identityHashCode()`** 를 활용한 메모리 주소 추적

## 🔎 코드 분석

### 1️⃣ **`String`의 불변성 (Immutable)**

```java
String str1 = "Java Powerful";
String str2 = new String("Java Powerful");
String str3 = str1 + str2;
String str4 = str1.concat(str2);
```

- `+` 연산을 사용할 경우 **새로운 `String` 객체가 생성됨**
- **`String` 객체는 변경 불가능(Immutable)** → 변경 시마다 새로운 메모리 할당

#### 📌 `System.identityHashCode()` 결과

```java
System.out.printf("%X\n", System.identityHashCode(str1));
System.out.printf("%X\n", System.identityHashCode(str2));
System.out.printf("%X\n", System.identityHashCode(str3));
System.out.printf("%X\n", System.identityHashCode(str4));
```

- `str1`과 `str2`는 **각각 다른 메모리 주소**
- `str3`, `str4`는 새로운 객체를 생성하여 **다른 메모리 주소를 가짐**

---

### 2️⃣ **`StringBuilder` 사용 (가변성)**

```java
StringBuilder str = new StringBuilder("");
```

- **`StringBuilder`는 가변(mutable) 객체**
- 문자열 연산 시 기존 객체를 수정하므로 **메모리 낭비 없음**

#### 📌 `StringBuilder.append()` 활용

```java
while(i<10) {
    str.append(i);  // 기존 객체에서 문자열을 수정
    System.out.printf("위치 : %x\n", System.identityHashCode(str));
    System.out.println("str : " + str + "\n");
    i++;
}
```

- `append()` 사용 시, **기존 객체의 메모리 주소 유지**
- **`String`의 `+` 연산과 달리 새로운 객체를 만들지 않음**

## 🔎 `String`, `StringBuilder`, `StringBuffer` 비교

|특징|`String`|`StringBuilder`|`StringBuffer`|
|---|---|---|---|
|**가변성**|불변(Immutable)|가변(Mutable)|가변(Mutable)|
|**연산 방식**|새로운 객체 생성|기존 객체 수정|기존 객체 수정|
|**성능**|느림 (새 객체 생성)|빠름 (동기화 없음)|느림 (`synchronized` 적용)|
|**스레드 안전성**|O (불변 객체)|X (스레드 안전 X)|O (멀티스레드 환경 가능)|

---

## 🔎 추가 정보

### 🔹 `StringBuffer` vs `StringBuilder`

- `StringBuffer`는 **멀티스레드 환경에서 동기화(synchronized) 지원**
- 단일 스레드 환경에서는 **`StringBuilder`가 성능적으로 더 우수**

#### `StringBuffer` 사용 예시 (멀티스레드 환경)

```java
StringBuffer buffer = new StringBuffer("Hello");
buffer.append(" World");
System.out.println(buffer);  // Hello World
```
