# 📝 Java 멀티스레드 동기화 + `wait()` & `notifyAll()` 문제 분석

## 📌 내용

- 공유 변수 `counter`를 `synchronized` 블록으로 보호
- `wait()`과 `notifyAll()`을 사용하여 스레드 간 협력
- `wait(1)`로 인해 불필요한 컨텍스트 스위칭 발생 가능

---

## 💻 문제 코드 분석

### ✅ **1. `synchronized (lock)` 블록 사용**

- `counter++` 연산을 동기화하여 레이스 컨디션 방지
- `lock.notifyAll()` 호출 → 다른 스레드에게 실행을 알림
- `lock.wait(1)` 호출 → **현재 스레드를 1ms 동안 대기 상태로 전환**

### ✅ **2. `wait(1)` 사용 문제점**

- `wait(1)`은 1ms 동안 현재 스레드를 멈추고 다시 실행 대기 상태로 이동
- 너무 짧은 대기 시간 → **스레드가 너무 자주 깨어나서 오버헤드 발생**
- 불필요한 `notifyAll()` 호출 → 성능 저하

---

## 🔎 실행 결과 예상 문제

- 스레드가 서로 **빠르게 깨어나고 대기하는 비효율적인 동작 발생**
- `wait(1)`이 짧은 간격으로 호출되면서 **스레드가 빈번하게 컨텍스트 스위칭**
- `notifyAll()`이 여러 번 호출되면서 **스레드 경쟁 증가**

---

## 🔧 해결 방법

### ✅ **방법 1: `wait()` & `notifyAll()` 제거 후 단순 동기화 적용**

- `wait()`와 `notifyAll()`이 불필요하게 스레드를 방해하므로 제거

```java
class IncrementThread implements Runnable {
    private static int counter = 0;
    private static final Object lock = new Object();

    public int getCounter() {
        return counter;
    }

    @Override
    public void run() {
        for (int i = 0; i < 100000; i++) {
            synchronized (lock) {
                counter++; // 공유 변수 증가
                System.out.println(Thread.currentThread().getName() + " counter : " + counter);
            }
        }
    }
}
```

- **동기화만 유지**하면서 스레드가 정상적으로 실행되도록 개선
- **불필요한 `wait()` 및 `notifyAll()` 제거**하여 성능 향상

---

### ✅ **방법 2: `AtomicInteger` 사용 (더 좋은 방식)**

- `AtomicInteger`는 `synchronized` 없이도 원자적 연산 보장

```java
import java.util.concurrent.atomic.AtomicInteger;

class IncrementThread implements Runnable {
    private static AtomicInteger counter = new AtomicInteger(0);

    public int getCounter() {
        return counter.get();
    }

    @Override
    public void run() {
        for (int i = 0; i < 100000; i++) {
            counter.incrementAndGet();  // 원자적 증가 연산
            System.out.println(Thread.currentThread().getName() + " counter : " + counter.get());
        }
    }
}
```

- `AtomicInteger.incrementAndGet()` 사용 → **불필요한 동기화 없이 스레드 안정성 유지**
- `synchronized`보다 **더 빠르고 효율적인 방법**

---

## 🔥 핵심 정리

- `synchronized` 블록으로 공유 변수 접근을 보호해야 함
- `wait()`과 `notifyAll()`을 잘못 사용하면 **불필요한 컨텍스트 스위칭으로 성능 저하 발생**
- `AtomicInteger`를 활용하면 동기화 없이 안전하게 증가 가능
- 성능을 고려한다면 **`AtomicInteger`가 더 나은 선택**
